# POS Deployment Progress

## Date: August 31, 2026

## Project Overview

Multi-tenant SaaS POS system for Kenyan SMEs (bars and restaurants). Built on the existing `joat_stores` platform.

**Client Requirements:**
- Bar and restaurant POS functionality
- Multiple waiters (single terminal per business for now)
- Customer tabs (M-Pesa or cash payment)
- M-Pesa STK Push from customer phone OR waiter-initiated from terminal
- Contact list for easy M-Pesa initiation
- Offline mode (hybrid approach — single terminal offline, sync when online)
- Admin dashboard for owner (real-time + EOD, mobile-friendly, exportable reports)
- Installable as PWA on Android, tablet, desktop

---

## Architecture Decisions

| Decision | Choice | Reasoning |
|----------|--------|-----------|
| Offline mode | Hybrid | Online for multi-terminal sync, offline for single terminal |
| App type | PWA | Works on all devices, no app store needed, existing Next.js stack |
| Multi-tenancy | Yes | Each bar/restaurant is a `store` (tenant) with JWT role-based access |
| Payment | M-Pesa + Cash | Daraja API (STK Push + C2B) |
| Hosting | Free tier | Supabase + Upstash + Render + Vercel |

## Issues Encountered & Resolved

### 1. Supabase SQL — Partial Unique Constraint Error
```
ERROR: syntax error at or near "WHERE"
CONSTRAINT uq_platform_admin_email UNIQUE (email) WHERE store_id IS NULL
```
**Fix:** PostgreSQL doesn't support inline partial unique constraints. Changed to separate `CREATE UNIQUE INDEX ... WHERE` statement.

### 2. Supabase SQL — Django PROTECT Error
```
ERROR: syntax error at or near "PROTECT"
ON DELETE PROTECT
```
**Fix:** `PROTECT` is Django-specific. Replaced with PostgreSQL equivalent `RESTRICT`.

### 3. Supabase SQL — Tables Already Exist
```
ERROR: relation "store_store" already exists
```
**Fix:** Added `DROP TABLE IF EXISTS` statements at top of SQL. Then had to use `DROP SCHEMA public CASCADE; CREATE SCHEMA public;` for complete cleanup.

### 4. Django Migrations — Duplicate Table Error
```
django.db.utils.ProgrammingError: relation "store_store" already exists
```
**Cause:** Manual SQL table creation conflicted with Django migrations.
**Fix:** Drop ALL tables, let Django migrations create proper schema, then seed data separately.

### 5. Admin Frontend — Wrong API URLs
```
404 on /auth/token/ (should be /api/v1/auth/token/)
```
**Cause:** `NEXT_PUBLIC_API_URL` was set to `https://joat-stores-api-qtde.onrender.com` but the frontend's axios `baseURL` appends paths like `/auth/token/`.
**Fix:** Updated `NEXT_PUBLIC_API_URL` to include `/api/v1` suffix:
```
https://joat-stores-api-qtde.onrender.com/api/v1
```

## Database Setup (Supabase)

### Method: SQL Editor (no Render shell access on free tier)

**Step 1 — Drop all tables:**
```sql
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
GRANT ALL ON SCHEMA public TO postgres;
GRANT ALL ON SCHEMA public TO anon;
GRANT ALL ON SCHEMA public TO authenticated;
GRANT ALL ON SCHEMA public TO service_role;
```

**Step 2 — Trigger Render deploy** (Manual Deploy → Deploy latest commit)
- Django migrations create all tables with correct schema
