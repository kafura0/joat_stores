# Story 3.10: Takeaway Order Type

Status: done

## Story

As a customer who wants to order ahead for pickup,
I want to place and pay for a takeaway order online and receive a pickup reference number.

## Acceptance Criteria

**AC1** — POST /api/v1/restaurant/orders/takeaway/ (AllowAny) → DineInOrder(order_type='takeaway', session=None) + KitchenTicket created immediately; table_number=0; phone required
**AC2** — POST /orders/takeaway/{id}/pay/ (AllowAny) → STK Push with reference=f"takeaway-{id}"; 429/502 on errors
**AC3** — payment_confirmed signal: reference.startswith("takeaway-") → send_takeaway_pickup_reference task dispatched; task generates TKW-NNNN (store-scoped count), sets order.pickup_reference, idempotent on retry
**AC4** — Kitchen COMPLETED → notify_takeaway_ready task dispatched (queue=notifications); stubs WhatsApp/SMS until Story 10.3

## Dev Notes

- order_type='dine_in' is the default — no migration data changes needed
- session=None is now allowed for DineInOrder (was CASCADE on non-null)
- TKW-NNNN generated by counting store-scoped takeaway orders — not globally unique
  but sufficient for display; Story 10.3 can replace with a sequence if needed
- pickup_reference idempotent: skips if already set (handles Celery retries)
- notify_takeaway_ready fires when kitchen transitions COMPLETED (mapped to DineInOrder.READY)
